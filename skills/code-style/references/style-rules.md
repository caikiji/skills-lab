# 写码规则

写码时逐条遵守。

## 体量

1. 只写被要求的代码:功能、分支、抽象、配置,未被要求的一律不写。
2. 写前先搜索项目内已有函数/库,能复用不新写。
3. 同一模式第一次出现直接写清楚,第二次出现才提取通用实现。
4. 交付前删净:未调用函数、未用 import、死分支、注释掉的代码块。

## 结构

5. 文件内固定顺序:职责注释 → imports → 常量/类型 → 纯函数 → 副作用函数 → 入口。
6. 新文件首行注释写职责:为什么存在、被谁使用。
7. 一个新主题开一个新文件,不塞进旧文件。
8. 命名可 grep:函数动词开头、变量名词、布尔 is_/has_ 前缀、常量全大写;禁止 a/tmp 这类无信息命名。
9. 纯函数不碰 IO;副作用函数(读写文件/网络/参数解析)集中在入口层。

## 信息

10. 注释写"为什么/边界/取舍",不写"是什么"(代码本身可读时)。
11. 嵌套≥2 层或步骤≥5 步的逻辑,拆成小函数,每函数顶部一句意图。
12. 导出函数、类方法写一句话用途:参数来源、返回含义。
13. 魔法数字用命名常量(0、1、-1 等公认语义值除外)。

## 硬阈值

| 项 | 阈值 |
|----|------|
| 函数体 | ≤50 行 |
| 文件 | ≤500 行 |
| 嵌套 | ≤3 层 |
| 位置参数 | ≤5 个 |
| 类型标注 | 函数签名、类属性、数据类字段全覆盖 |
