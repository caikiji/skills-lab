# Code Style

## 流程

1. 写码前读 `references/style-rules.md`;纯查询/只读问答直接回答,不执行本流程。
2. 回答开头写一句边界:本次写什么、不写什么(多余抽象、未要求功能、提前泛化一律不写)。
3. 按 style-rules.md 写码。
4. 交付前按 style-rules.md 逐条自检,未通过先修再交付。
5. 回答末尾输出「## 变更导航」,四个小节齐全,无内容写「无」,每项一句话。

## 变更导航格式

```
## 变更导航
- 改动一览:每文件一行,职责一句话
- 阅读顺序:入口 → 依赖,每步一句理由
- 关键决策:每处一句话,为什么这么写
- 缺陷提示:未覆盖/需人工确认处,每项一句
```

## 边界

- 阈值与项目约定冲突时,先告知用户。
- 历史遗留代码不规范:只提示,不修改。
- 文档/README、提交信息、AGENTS.md 分别走 readme-style、commit-style、agents-style。
