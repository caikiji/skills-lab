# Workflow 检查点协议

## 触发时机

加载后先判断：任务需多步执行（探索→方案→实现→验证等）则启用；纯闲聊、一次性问答、单个简单命令不启用，声明"本任务不启用协议"后照常执行，不输出检查点。

启用后按下列 4 个检查点执行直到任务结束。

## 流程

1. **任务理解**（接活即输出）：目标是什么、执行步骤、关键假设与风险。
2. **初版方案**（探索完成后输出）：方案要点、备选与取舍、所需依赖/信息。
3. **复盘**（命中量化条件立即暂停当前动作输出）：问题是什么、已有信息、尝试过什么及为何无效、最终怎么解决的。
4. **最终汇报**（任务结束，成败皆报）：做了什么、怎么做的（含复盘汇总）、结果（完成/未完成/遗留问题）。

量化条件（命中任一条即触发步骤 3）：

- 方案被推翻，或需求/约束变更
- 连续 ≥3 轮工具调用无实质进展
- 同一问题尝试 ≥2 种方法仍失败，或被迫换思路

## 门控规则

- 步骤 1（任务理解）：输出后必停，等用户确认后再探索。
- 步骤 2（初版方案）：按探索已知事实判定——
  - 暂停：计划修改 ≥2 个文件；或计划含提交/推送/部署、删除文件、修改外部服务配置。
  - 继续：仅读取/查询；或单文件改动且不含上述动作。
- 用户声明"无需确认"时豁免：输出后继续。
- 每次报告末尾写明下一步计划。

## 输出规范

每个检查点按统一模板输出：

```text
【阶段】理解 / 方案 / 复盘 / 汇报
摘要：≤5 行
关键信息：…
决策与取舍：…（复盘阶段替换为：问题 → 已有信息 → 解决手段）
下一步：…
状态：理解✓ / 方案✓ / 完成 / 受阻
```

同步落盘：每次检查点输出按下方模板完整呈现，并同步追加到 `<项目根>/.temp/workflow-log/<YYYY-MM-DD>.md`（内容同对话），条目格式为 `## [HH:MM] 阶段X` + 模板内容，文件不存在则创建。

## 边界

- 专项动作（如 git 提交）仍遵守对应技能（如 commit-style），本协议不重复其规则。
- 复盘发现某技能方案有缺陷时，提示可触发 skill-feedback 沉淀，不自动执行。
- 本协议只追加自己的落盘文件，不修改其它文件。
