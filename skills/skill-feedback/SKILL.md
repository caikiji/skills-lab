# Skill Feedback

把某次任务中使用其它 skill 时踩到的坑与已验证的替代方案写成反馈报告，落盘 `.temp/skill-feedback/`。

## 触发时机

- **自动**：任务使用了其它 skill，其指引缺失、报错或过时，且本会话已找到替代做法——任务收尾后立即执行下方流程。
- **显式**：用户要求"记录/反思/沉淀对某个 skill 的反馈"。
- **不落盘**（仅口头提醒）：缺陷源于环境而非 skill 内容；替代方案未在本会话验证成功；提不出可操作的修改建议。

## 流程

1. 主任务未完成时先完成主任务；关键证据（报错输出等）即将丢失时，先在回复中记下要点。
2. 重读目标 skill 相关文件，引用有欠缺的原文片段及文件路径；核对本会话替代方案的实际命令与输出。禁止凭记忆转述 skill 内容。
3. 三条全满足才写报告：① 缺陷出在 skill 内容本身；② 替代方案已在本会话跑通；③ 结论可迁移复现，非一次性本地状态。任一不满足则只口头提醒。
4. 读 [references/templates.md](references/templates.md)，按模板写入 `.temp/skill-feedback/<目标skill名>/<YYYY-MM-DD>-<主题短语>.md`，目录不存在则创建。写入前查同目录 index.md：已有同主题待处理报告则照常新增，双方在"备注"互链。
5. 按模板更新该目录 index.md，新记录追加到表格末尾。
6. 告知用户报告路径 + 一句话摘要。

## 报告规范

- 自包含：读者没有本会话上下文也能看懂问题与解法。
- 中文书写；命令、路径、报错原样粘贴，不转述。
- 元信息必填安装路径与来源；目标来自上游同步仓库（如本项目 `.git-remote-files` 管理的技能）时注明"改动应提交上游"，本地改动会被覆盖。
- 同日同主题重复报告文件名尾部加 `-2`、`-3` 序号。

## 边界

- 只写 `.temp/skill-feedback/` 目录；绝不修改任何 skill 文件或全局配置。
- 不要清理已有报告。
