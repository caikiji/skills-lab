# 卡片类型与切分规则

## 类型词表

| 类型 | 用途 | 要点内容 |
|------|------|---------|
| 总卡 | 第一张，模块全景 | 子卡标题列表（豁免锚点与字数上限） |
| 概念卡 | 是什么：数据结构、核心模型、术语 | 含锚点的定义要点 |
| 流程卡 | 怎么流转：调用链、状态机、数据流 | 含锚点的流转步骤 |
| 决策卡 | 为什么：设计取舍、选型理由 | 含锚点的决策与理由 |
| 陷阱卡 | 哪里会出错：边界条件、已知坑 | 含锚点的坑与触发条件 |
| 接口卡 | 对外暴露什么：签名、配置、协议 | 含锚点的接口清单 |

## 切分规则

1. 先出总卡：一句话概括模块 + 要点列出全部子卡标题。
2. 子卡按六维度（入口/数据/流程/决策/接口/陷阱）取模块实际有的子集，一卡只讲一件事。
3. 子卡 3~8 张，总张数 4~9；讲不下就再切，超过上限说明模块太大，先拆模块再卡片化。
4. 关联行写卡间关系：`← 卡N` 表引用来源，`→ 卡M` 表本卡引出。

## 各类型要点写法

- 概念卡：`- <名称> <一句话定义>（<定义所在 文件:行号>）`
- 流程卡：`- <步骤>（<函数调用 文件:行号>）`
- 决策卡：`- <选择> 因为 <原因>（<代码位置 文件:行号>）`
- 陷阱卡：`- <坑> 触发条件是 <条件>（<代码位置 文件:行号>）`
- 接口卡：`- <签名或配置>（<文件:行号>）`
